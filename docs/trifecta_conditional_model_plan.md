# 三連単 条件付き確率モデル化 計画

## 目的
三連単を一気に完成させず、`1着 -> 2着条件付き -> 3着条件付き -> 再構成` の順で安全に進める。
各 phase で中間成果物と採用判定を明文化し、失敗時に戻れる構造にする。

## 前提
- 学習対象は `1レース×1艇` の縦持ちデータを基本とする。
- 1着モデルは公式 baseline として固定済みの `core` / `core_relative` 系を参照する。
- 本設計は、三連単確率の再構成を最終目標とするが、selector 接続は最後に行う。

## 評価指標
各 phase で、少なくとも次を確認する。
- `log loss`
- `Brier score`
- `calibration`
- `top1`
- `top3`
- `BUY候補の ROI`

## Baseline の定義
### Naive baseline
2着・3着の比較対象として、まず naive baseline を置く。
- 2着: 1着候補を固定したときの単純な残り艇一様分布
- 3着: 1着・2着候補を固定したときの単純な残り艇一様分布
- 三連単: 上記の積で再構成した独立近似

Naive baseline は「最低限ここまでは超えるべき」基準として扱う。

## Phase 1: 1着モデル固定
### 目的
1着モデルを安定した入力・出力・評価の土台として固定する。

### 入力データ
- `data/processed/trainable_win_training_data.csv`
- `config/feature_sets/win_baseline_core.json`
- `config/feature_sets/win_baseline_extended.json`
- `config/feature_sets/win_baseline_core_relative.json` 相当の比較結果

### 出力成果物
- 1着モデルの学習・評価レポート
- 採用済み feature set の固定メモ
- 時系列 split の再現可能な記録

### 採用判定条件
- time split が安定して再現可能
- `core` / `core_relative` の差分が明文化されている
- calibration の悪化が許容範囲

### 次フェーズへ進む条件
- 1着予測の出力が他 phase の入力として安定利用できる

## Phase 2: 2着条件付きモデル
### 目的
`P(2着 | 1着固定)` を学習し、1着候補を前提にした2着分布を得る。

### 入力データ
- 1着モデルの出力
- レース内の艇順・除外条件
- 2着教師ラベル

### 出力成果物
- `2着条件付き確率`
- 2着候補ランキング
- 2着モデルの評価レポート

### 採用判定条件
- naive baseline を log loss / calibration / top3 で上回る
- 1着固定後の2着分布が崩れていない

### 次フェーズへ進む条件
- 1着固定後の2着候補を stable に返せる

## Phase 3: 1着+2着 の中間評価
### 目的
`1着 -> 2着` の中間までを連結し、部分的な三連単再現性を評価する。

### 入力データ
- Phase 1 の 1着出力
- Phase 2 の 2着条件付き出力

### 出力成果物
- `1着+2着` の部分経路確率
- top2 / top3 部分評価
- 2段構成の誤差分解レポート

### 採用判定条件
- 単体の1着/2着評価より、連結後の top2 / top3 が改善する

### 次フェーズへ進む条件
- 2着の条件付き確率を三連単再構成へ流せる

## Phase 4: 3着条件付きモデル
### 目的
`P(3着 | 1着, 2着 固定)` を学習する。

### 入力データ
- 1着候補
- 2着候補
- レース内残余艇の特徴量
- 3着教師ラベル

### 出力成果物
- 3着条件付き確率
- 3着候補ランキング
- 3着モデルの評価レポート

### 採用判定条件
- naive baseline を log loss / calibration / top3 で上回る

### 次フェーズへ進む条件
- 3段の条件付き確率が同一レース内で整合する

## Phase 5: 三連単確率再構成
### 目的
`P(1着,2着,3着)` を再構成し、三連単候補全体の確率を出す。

### 入力データ
- 1着条件付き確率
- 2着条件付き確率
- 3着条件付き確率
- 補正用の順序制約

### 出力成果物
- 三連単確率
- 三連単ランキング
- naive baseline との差分レポート

### 採用判定条件
- top1 / top3 / calibration が naive baseline を安定して上回る
- 候補の確率和がレース内で破綻しない

### 次フェーズへ進む条件
- selector が使える形の三連単候補出力が安定する

## Phase 6: calibration と selector 接続
### 目的
三連単確率を校正し、selector に接続する。

### 入力データ
- Phase 5 の三連単確率
- 実オッズ
- selector の実行可能性 gate

### 出力成果物
- 校正済み三連単候補
- BUY/WATCH/SKIP 連携レポート
- ROI・購入件数・実行可能性の統合評価

### 採用判定条件
- `BUY候補の ROI` が悪化しない
- calibration が selector 接続後も維持される

### 次フェーズへ進む条件
- 日次 replay と selector が一貫した出力を返す

## 実装順序の原則
1. 1着モデルを固定する
2. 2着条件付きモデルを作る
3. 1着+2着の中間評価を入れる
4. 3着条件付きモデルを作る
5. 三連単再構成を行う
6. 最後に selector を触る

## 失敗時の戻り方
- Phase 2 で失敗したら Phase 1 に戻る
- Phase 4 で失敗したら Phase 2 まで戻る
- Phase 5 で失敗したら Phase 3 まで戻る
- Phase 6 で失敗したら selector を戻して校正だけやり直す

## コメント
この計画では、三連単を「一気に完成」させない。
中間成果物ごとに評価し、採用条件を満たさない phase は先へ進めない。
